Get your Hero Screen online.

Five steps from a blank machine to your own live, interactive web page — the stage you'll art-direct all term. No coding experience needed. Every command is written out; you never have to invent one.

First — which computer are you on?

Scroll to begin ↓
1 Install your tools

Set up your workshop.

You need four free things, once: a place to host your site (GitHub), the tools that build and move your code (Node and Git), and an editor to work in (VS Code). Install them and you never think about them again.

  1. Create a free GitHub account

    At github.com — use an email you'll keep. Skip if you already have one.

  2. Install VS Code

    Your editor — code.visualstudio.com. Don't use Notepad or TextEdit; they quietly break code files.

  3. Install Git
    macOS

    Open Terminal (press ⌘-Space, type Terminal, Enter) and run this. A window pops up — click Install. It takes a few minutes.

    xcode-select --install
    Windows

    Download from git-scm.com and run the installer — accept every default (one of them is the browser sign-in you'll use later).

  4. Install Node.js

    Go to nodejs.org and click the big green LTS button (the stable one — take whatever number it shows). Open the downloaded installer and click through it.

  5. Check it worked

    Quit Terminal completely (⌘-Q), open it fresh, and run all three:

    Open the Start menu, type Terminal, and press Enter. In that window, run all three:

    git --version
node -v
npm -v
Done when: all three commands print a version number — not command not found or not recognized.
Something "not found"? You installed it but the terminal was already open. Close it completely and open a fresh one — it only sees new tools in a new window.
2 Claim your copy

Make it yours from the start.

You won't build inside the class starter — you'll spin up your own copy of it. GitHub's Use this template gives you a fresh repository you fully own, with its own clean history. All in the browser; nothing to type.

  1. Open the starter

    Go to github.com/profangrybeard/Vanilla_Claude.

  2. Click the green “Use this template”

    Then choose Create a new repository.

  3. Name it anything you like

    Owner is you. Pick any name — lowercase-with-hyphens is easiest, e.g. my-hero-screen.

  4. Set visibility to Public

    Required for a free live site. Then click Create repository from template.

Name it whatever you want. The project is set up so any repo name just works — you never edit a “base path” or config. If a tutorial ever tells you to, you can ignore it here.
Done when: you're looking at your own new repo — your username at the top — holding the same set of files.
3 Turn on the website

Flip the site switch.

Your repo can publish itself to a real web address every time you save your work to it. You just switch it on once. (It goes live for real in Step 5 — this only arms it.)

  1. In your new repo, click Settings

    Top row of the repo page.

  2. In the left sidebar, click Pages

    Under “Code and automation.”

  3. Set the Source

    Under Build and deployment → Source, choose GitHub Actions from the dropdown.

Keep the repo Public. On a free GitHub account, a private repo can't publish a live site.
Done when: the Source shows GitHub Actions. Nothing's live yet — that's Step 5.
4 Run it on your computer

Bring it down and press play.

Copy your repo onto your machine, then start the live-preview server — it shows your page in the browser and refreshes the instant you save a change.

  1. Copy your repo's link

    On your repo, click the green Code button → HTTPS → copy the URL.

  2. Open a terminal in a sensible folder
    macOS

    Open Terminal, then move into your Documents folder:

    cd ~/Documents
    Windows

    Open File Explorer → your Documents folder → right-click empty space inside it → Open in Terminal.

  3. Download it, then step inside

    Paste your URL after git clone, then cd into the folder it creates (use your repo's name):

    git clone PASTE-YOUR-URL-HERE
cd your-repo-name
  4. Tell Git who you are — first time only

    Use the email on your GitHub account.

    git config --global user.name "Your Name"
git config --global user.email "you@example.com"
  5. Install and run

    npm install takes a minute and prints a wall of text — that's normal.

    npm install
npm run dev

    Open the address it prints (like http://localhost:5173/) — ⌘-click itCtrl-click it or paste it into your browser.

Done when: a page loads at that localhost address — this very setup guide, now running from your own copy. That's the project working on your machine; your Hero Screen will replace this page.
The terminal is now busy running the server. Leave it open. Press Ctrl+C to stop it; open a second terminal if you need to type other commands.
5 Ship it live

Save to the cloud, go live.

This is the loop you'll use all term: edit → save → push. Pushing sends your work up to GitHub, which rebuilds your live site automatically. Let's prove it with one tiny change.

  1. Open the project in VS Code

    File → Open Folder → pick your repo folder. The file tree appears on the left.

  2. Make one small change

    Open index.html, change the text between <title> and </title>, and save (⌘-SCtrl-S).

  3. Set up your sign-in — first push only
    macOS

    Install Git Credential Manager so pushing signs you in through your browser (same as Windows). On the GCM releases page, download the file ending in .pkg, double-click, and install.

    No-install alternative: when the terminal later asks for a Password, paste a token instead of your password — github.com → your avatar → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate, check the repo box, set a long expiration, copy it, and paste at the prompt (it stays invisible — that's normal).

    Windows

    Nothing to install — the sign-in window appears by itself on your first push (next step).

  4. Save and send it up
    git add .
git commit -m "My first change"
git push

    On your first push you'll be asked to sign in — a browser window opens; sign in once and it's remembered. (If you took the token route above instead, paste your token at the Password prompt — it stays invisible as you paste, which is normal.)

  5. Watch it deploy, then visit it

    On GitHub, open the Actions tab. A yellow dot means building; a green check means live. Your address is:

    https://YOUR-USERNAME.github.io/your-repo-name/
Done when: your live URL loads the starter. Open it in a private / incognito window — that's the real test. First time, give it 1–2 minutes after the green check and hard-refresh (⌘Ctrl-Shift-R).

If something breaks

Quick fixes.

Every one of these is common and harmless. Nothing here means you broke something permanently.

command not found / not recognized
You installed the tool but the terminal was already open. Close every terminal and open a fresh one.
the terminal seems stuck after npm run dev
It's not stuck — the preview server is running. Ctrl+C stops it; open a second terminal for other commands.
fatal: not a git repository
Your terminal isn't inside the project. cd into your repo folder (Step 4).
Author identity unknown
Run the two git config --global lines from Step 4.
password authentication … removed
GitHub doesn't take your password. Use the browser sign-in (or a token on macOS) — Step 5.
Actions shows a red ✕ the first time
Make sure Pages Source is GitHub Actions (Step 3), then re-run the job from the Actions tab.
live page is blank or 404 right after the green check
First deploy lags. Wait 1–2 minutes, hard-refresh, try incognito.
